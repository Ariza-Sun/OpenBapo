# 第 4 步实现计划：渲染与导出（三层谱）

> 对应：`docs/ROADMAP.md` 第 4 步；需求 `docs/REQUIREMENTS.md` 5.6（导出）、附录排版参考；`docs/plans/backend.md` 第 4 节。
> 状态：2026-11-15 修复节奏时值与参考谱画法；新样张和回归记录见第 11 节。2026-11-11 的看图记录保留在第 8 节，不能作为本次新画法已经通过人工验收的依据。

## 1. 目标与范围

把第 3 步的 `ArrangedSheet` 画成谱：和弦图条、六线谱节奏型行、简谱行（本步留空位）、歌词行（本步占位）、页眉、小节线与小节号；出 SVG、PNG（第一页预览）、多页 PDF，以及可导入 MuseScore 精修的 MusicXML。排版以 `docs/reference/desperado-sheet.webp` 为标准。

**本步做**：

1. SVG 排版引擎：A4 纵向，一个"系统"= 和弦图条 + 六线谱行 + 简谱行 + 歌词行，每行 4 小节；页眉（标题、演唱者、`♩= BPM`、`1=X 拍号`、原调 / 演唱调 / 指法调 / 变调夹）；自动分页。
2. 六线谱行：扫弦用谱内竖箭头，下方独立标节奏；分解在被拨的弦上画 ×。符干、符尾、符杠、附点、延音和休止由完整时值计算。"无"节奏型只标和弦变化及其持续时值。
3. 简谱行：本步画出行的位置与小节线；音符（M2，第 7 步）暂不画。`notes` 不为空时按最简规则画数字（音级、高低点、整拍一个数字），不做下划线 / 附点 / 连音线的细排版。
4. 歌词行：本步占位（`lyrics` 为空时留白；不为空时按音节起始时间摆到对应拍的位置）。
5. 低置信和弦：和弦名用灰色并加 `?`。
6. SVG → PNG（cairosvg）、SVG 多页 → PDF（cairosvg 逐页 + pypdf 合并）。
7. MusicXML：和弦符号（`harmony`）+ 六线谱（TAB 谱表，节奏型的弦 / 品）+ 歌词音节 + 一条标准谱表（放和弦符号与以后的旋律）。
8. `openbapo render` 命令：读 sheet JSON，写 `--svg DIR`、`--png FILE`（第一页）、`--pdf FILE`、`--musicxml FILE`。

**本步不做**：简谱时值记号的细排版（下划线、附点、连音线、跨行连线，第 7 步）；真实歌词（第 5 步）；Discord 交互；排版的可配置项（字号、每行小节数等先固定）。

## 2. 设计

### 2.1 模块

```
src/openbapo/render/
    __init__.py      # render_svg / render_png / render_pdf / render_musicxml
    layout.py        # 尺寸常量；把 bars 切成系统与页；每小节内拍的 x 坐标
    rhythm.py        # SVG / MusicXML 共用：时值、延音、休止、发声弦及连杠分组
    svg.py           # 画：页眉、和弦图、六线谱行、简谱行、歌词行、小节线、小节号
    export.py        # SVG → PNG / PDF
    musicxml.py      # ArrangedSheet → MusicXML 文本
```

依赖新增可选组 `openbapo[render]`：`cairosvg`（PNG / PDF，需系统 libcairo）、`pypdf`（合并页）。MusicXML 用标准库 `xml.etree` 直接写，不引入 music21；测试用 `music21` 读回校验（只进 `dev` 组）。

### 2.2 坐标与分页（`layout.py`）

- 页面 A4：595 × 842 pt，边距 40 pt。所有尺寸以 pt 为单位写成常量。
- 系统高度固定 149 pt；六线谱弦距 5.5 pt；第一页页眉 96 pt；当前 A4 每页放 4 个系统。
- 每行 4 小节，小节等宽；小节内第 k 拍的 x = 左边 + (k + 0.5 的余量) × 拍宽。`BarChord.beat`、节奏型 `events.beat`、音符与歌词的拍位置都映射到同一套 x。
- 第一小节左侧留出谱号区（TAB 字样 + 拍号）。

### 2.3 画法（`svg.py`）

- **和弦图**：5 品 × 6 弦的网格，23 × 26 pt；`base_fret > 1` 时左侧写品位数；× / ○ 画在上沿；横按以各弦的按弦点表示。和弦图与和弦名的中心共同对齐起拍 x。同一小节两个和弦并排。
- **六线谱行**：扫弦用覆盖发声弦的细线竖箭头、空心箭头尖（朝高音弦为下扫），节奏符干独立放在六线谱下方；上扫只拨最高的四根可发声弦。闷音在箭头上方加点；分解在被拨的弦上画 ×，符干从最下方的 × 向下延伸。SVG 与 MusicXML 从 `rhythm.py` 取得相同的时值、弦和动作。跨拍延音拆分后加延音线，扫弦续符用短横和节奏符干表示，只有起音处有箭头；长音用四分时值的起音和后续短横表示。独立八分有符尾，6/8 默认 3+3 分组。不完全小节保留实际长度并标注，不补造起音。
- **简谱行**：`1=X` 已在页眉；有音符时画行内小节线；有音符时每个整拍位置写音级数字，高低八度画上下点，休止写 0。
- **歌词行**：音节文字放到其起拍 x。
- **低置信**：和弦名 `#666` 灰色，后缀 `?`。
- 字体：`font-family="Noto Sans CJK SC, Noto Sans SC, PingFang SC, Microsoft YaHei, sans-serif"`；数字与英文用同一字体。PNG 渲染依赖系统装有其中之一，README 写明（Linux：`fonts-noto-cjk`）。

### 2.4 MusicXML（`musicxml.py`）

- `score-partwise` 4.0 版；两个 part：P1 标准谱表（高音谱号，`harmony` 和弦符号，本步只有休止符占位，以后放旋律与歌词），P2 TAB（`clef sign=TAB`，`staff-details` 六弦标准调弦，节奏型事件写成 `note` + `technical/string` + `technical/fret`，扫弦事件用和弦音 chord 叠加）。
- 歌词音节挂在 P1 的音符上；本步 P1 无音符时歌词不写（第 5 步接）。
- 和弦符号按**发声**音高写（`root-step` / `root-alter`），另加 `capo` 的 `transpose` 到 P2，MuseScore 据此显示指法调的和弦名。简化开关按显示名写。
- 测试用 music21 解析：part 数、measure 数、harmony 数、TAB 弦品数都能读回。

### 2.5 CLI

```
openbapo render SHEET.json [--svg DIR] [--png FILE] [--pdf FILE] [--musicxml FILE] [--dpi 150]
```

### 2.6 性能

SVG 是字符串拼接；一首 4 分钟歌约 100 小节、25 个系统、6 页。cairosvg 栅格 150 dpi 一页约 0.3 s。预算 5 秒内。`scripts/time_pipeline.py` 加 `render` 环节记录。

## 8. 负责人决定

> 负责人指示"做第四步，一起看结果"：以下按推荐项实现，排版细节以看图反馈为准。

### 1. 四层全部自绘 SVG，不引入排版库

- 中文简谱式弹唱谱没有现成库能画（简谱是硬需求），六线谱节奏型行很简单，自绘最可控；alphaTab / Verovio 画的是西式六线谱，风格与参考谱不合，还要多一套运行时。
- PNG / PDF 用 cairosvg（纯 Python 包 + 系统 libcairo，PDF 是矢量）。

### 2. MusicXML 直接写 XML，不用 music21 生成

- 要写的元素很少（和弦符号、TAB 音符、歌词），标准库够用；music21 包 20 MB，只在测试里读回校验。

### 3. 字体用系统的思源黑体（Noto Sans CJK），不随仓库分发

- 字体文件十几 MB，仓库不放；SVG 里写字体族回退列表，PNG 渲染机器装 `fonts-noto-cjk`（OFL 许可）。

### 4. 记录：负责人看图后的三处修改（2026-11-11）

- 扫弦：改为穿过各发声弦的竖箭头，箭头朝上（指向高音弦）为下扫、朝下为上扫；闷音在箭头旁加点；分解在被拨的弦上画 ×。最初的"每弦 × + 谱上小箭头"不合中文弹唱谱习惯。
- 横按：每根被按住的弦画一个点，不画横杠；横按不在第 1 品时图从横按那一品画起，左边标起始品位。
- F（及 Fm）的默认按法改为大横按（133211），与曲库各家谱子一致；四弦小 F 留作备选。
- 依据：对照负责人曲库中老姚吉他、小LV 吉他、山山吉他、南屏晚钟等谱子的原图。
- 开放问题 7.1、7.2（空行是否缩小、节奏型是否每小节重复）负责人未要求修改，维持现状。

## 11. 2026-11-15：修复缺半拍与谱面画法

负责人指出《小星星》的民谣节奏按符号只能读出 3.5 拍，并要求参考给定谱子的画法。根因是旧 `_beams()` 根据起音间隔连杠，把起点 1.5、持续 1 拍的上扫误写成八分；符杠分组也会跨越应断开的拍边界。

- 新增共用时值层：以 Fraction 保留拍位置，按拍号分母换算音符时值；补全休止，跨拍拆分并用延音连接。民谣节奏仍有六次起音，图上的延音续符不产生额外扫弦。
- 6/8：六个内部拍等于六个八分音符；默认按 3+3 连杠。MusicXML 的 duration、和弦/歌词 offset、速度单位一并换算。切音导出为 × 音头的击弦事件，上扫使用和图片相同的发声弦。
- 和弦图缩小、居中对齐；空简谱不再画孤立小节线。扫弦画法经负责人指出后按曲库原图纠正，见第 12 节；第 8 节的历史看图结论不覆盖此次改动。
- `scripts/render_samples.py` 可复现小星星的三种节奏样张及 6/8 对照图。已知谱面样张用于渲染验收；历史分析另存出图，保留其多检尾拍，不能混用这两组结果证明识别准确率。
- 回归覆盖库中全部 14 种节奏型的拍数和起音、延音、符尾、附点、十六分短杠、6/8、休止、不完全小节与 MusicXML 读回。性能结果见 `docs/benchmarks/step-4-rhythm-timing.md`。
- 新画法已生成可查看的样张，最终视觉评价以负责人对新图的反馈为准；本次未运行 MuseScore 图形界面，不将自动读回表述为 MuseScore 人工验收。

## 12. 2026-11-15：扫弦符号以 dataset 原图为准

负责人明确指出“谱子扫弦不长这样”，要求查看提供的实例 dataset。此前将参考图中的分解拨弦 × 套用于扫弦，是实现误判，不是负责人选择的样式。

- 已目视检查本地 `sheets-input/triage` 中四首曲目的原页，以及 `sheets-batch` 中两张行级放大图，包含老姚吉他、小 LV 吉他、山山吉他的版本。同一原页中并存的扫弦与分解段直接区分了竖箭头和 ×；原图及私人歌名清单不复制进仓库。
- 扫弦：谱内细竖线与空心箭头尖；箭头所在 x 与下方节奏符干对齐。不能画成各弦一列 × 加旁边的小箭头，也不能用实心三角箭头尖。
- 曲库样本的扫弦箭头与下方节奏符干有间隔；分解的 × 则连接向下的符干。本次据此修正第 8 节早期“连续符干”的实现。
- 闷音点放在箭头上方，与谱下的时值附点分开。长音延续用短横；跨拍拆分的续符保留延音线和准确时值，不产生新起音。
- 测试从实际 SVG 路径坐标核对箭头方向、覆盖弦范围、与符干的对齐及间隔，并区分扫弦、分解、闷音、延续；同时保留全部 14 种节奏型的时值与导出回归。视觉样张仍由 `scripts/render_samples.py` 生成。
- 负责人查看这一版修正说明及样张后回复“好的”，本版作为后续扫弦画法基准。
